# Migrating to 0.10.0

`0.10.0` closes a cross-namespace information-disclosure vulnerability
([CVE-2026-54495](https://github.com/open-feature/open-feature-operator/security/advisories/GHSA-398h-7f66-3h4p)).
The change is **breaking**: namespaced `FeatureFlagSource` and `InProcessConfiguration` resources can no longer be
referenced from another namespace. This guide explains how to migrate.

## What changed

- The `openfeature.dev/featureflagsource` and `openfeature.dev/inprocessconfiguration` annotations now reject
  cross-namespace references (`{OTHER_NAMESPACE}/{NAME}`). Bare names and the same-namespace explicit form
  (`{OWN_NAMESPACE}/{NAME}`) still work.
- A namespaced `FeatureFlagSource` may no longer list a `kubernetes`, `file` or `flagd-proxy` source in another
  namespace. Pods that use it are denied at admission, and a `Flagd` that uses it fails to reconcile.
- A source without a `provider` now takes the `defaultSyncProvider` of its own `FeatureFlagSource` (or the operator
  default), not one set by another source merged into the same pod.
- Two new cluster-scoped resources, `ClusterFeatureFlagSource` and `ClusterInProcessConfiguration`, provide a
  sanctioned way to share configuration across namespaces. They are referenced via the new
  `openfeature.dev/clusterfeatureflagsource` and `openfeature.dev/clusterinprocessconfiguration` annotations.
- The `flagd-kubernetes-sync` read permission is now granted per-namespace for namespaced sources.

## 1. Find affected workloads

List pods whose annotation uses a cross-namespace reference. This snippet flags any `featureflagsource` /
`inprocessconfiguration` annotation value containing a `/` whose namespace differs from the pod's own:

```sh
kubectl get pods -A -o json | jq -r '
  .items[]
  | .metadata as $m
  | ($m.annotations // {}) as $a
  | ($a["openfeature.dev/featureflagsource"], $a["openfeature.dev/inprocessconfiguration"])
  | select(. != null)
  | split(",")[]
  | gsub("^\\s+|\\s+$";"")
  | select(contains("/"))
  | select(startswith($m.namespace + "/") | not)
  | "\($m.namespace)/\($m.name): \(.)"'
```

Also list pods that hold the legacy kubernetes-sync marker (see step 3):

```sh
kubectl get pods -A -l openfeature.dev/allowkubernetessync=true
```

## 2. Migrate the references

For each affected workload, choose one:

### The source is meant to be same-namespace

If the referenced resource actually lives in the pod's namespace, the `{NAMESPACE}/` prefix was redundant. Drop it
(or keep the explicit `{OWN_NAMESPACE}/{NAME}` form). No further change needed.

### The source is meant to be shared across namespaces

Recreate it as a cluster-scoped resource and update the annotation. For example, a workload in `team-a` that
referenced `platform/shared-config`:

```yaml
# before (rejected in 0.10.0)
annotations:
  openfeature.dev/featureflagsource: "platform/shared-config"
```

Create a `ClusterFeatureFlagSource` (cluster-admin action). Note its inner `sources[].source` values must be
namespace-qualified:

```yaml
apiVersion: core.openfeature.dev/v1beta1
kind: ClusterFeatureFlagSource
metadata:
  name: shared-config
spec:
  sources:
    - source: platform/my-flags
      provider: kubernetes
```

```yaml
# after
annotations:
  openfeature.dev/clusterfeatureflagsource: "shared-config"
```

The same pattern applies to `InProcessConfiguration` → `ClusterInProcessConfiguration` via the
`openfeature.dev/clusterinprocessconfiguration` annotation.

## 3. Restart kubernetes-sync workloads

Pods admitted before the upgrade carry only the legacy `openfeature.dev/allowkubernetessync=true` marker (no scope
marker). On the first boot of `0.10.0` the operator treats them as cluster-scoped and preserves their existing
cluster-wide read access, so nothing breaks. However, **the advisory is not fully closed for those pods until they are
restarted and re-admitted**, at which point they receive per-namespace read access and the new scope marker.

After upgrading, roll the affected workloads so they pick up the tightened permissions:

```sh
# example: restart every deployment in a namespace that uses kubernetes sync
kubectl rollout restart deployment -n <namespace>
```

## Note on namespace-scoped operator installs

A namespace-scoped operator install (see
[#795](https://github.com/open-feature/open-feature-operator/issues/795)) will not include the cluster-scoped CRDs;
the `Cluster*` resources require a cluster-scoped install.
